# 해치와 한국어 — 예문 빈칸 문제 설계서 (v0.4)

- 날짜: 2026-11-06
- 바탕: v0.1·v0.2 설계서, v0.3 설계서 `2026-11-06-번체-옵션-설계.md` (규칙은 그대로, 이 문서는 바뀌는 점만)
- 순서: v0.3(뜻 반영 → 번체)을 끝낸 뒤 진행한다. 번체판은 빌드 변환으로 예문도 자동으로 따라간다.

## 1. 의도

뜻이 여러 개이거나 문맥이 있어야 정해지는 단어(차, 안, 신고, 모델 …)를 문장 속에서 익힌다.
카드 클릭 방식(타이핑·듣기 없음)은 그대로다.

성공 기준:
1. 예문이 있는 단어(처음 110개: 재검수 109개 + 2장 「안」, 아래 3.1)는 레슨에서 빈칸 문제로 한 번 이상 나온다.
2. 빈칸 문제의 보기 4장은 모두 같은 꼴(사전형)이라 활용형으로 정답이 드러나지 않는다.
3. 예문 한국어·중국어는 교차 검토(일반·문학 번역)를 거친 것만 앱에 나온다. 보류한 예문은 나오지 않는다.
4. 레슨 수·레슨 id·문제 수는 그대로라 기존 저장이 유효하다.

범위 밖: 1,941개 전체 예문, 장별 문법 목록 정리, 예문 듣기, 예문 직접 입력, 빈칸이 둘 이상인 문장.

## 2. 화면

```
[예문 빈칸]                         ← 문제 머리 「选出填入空白处的单词」
  냉장고 ＿＿에 우유가 있어요.       ← 한국어 예문(크게), 빈칸 ＿＿
  冰箱里有牛奶。                    ← 중국어 번역(작게, 힌트)
  ┌────┐ ┌────┐ ┌────┐ ┌────┐
  │ 안  │ │ 밖  │ │ 위  │ │ 옆  │     ← 사전형 카드 4장, 고르고 「确认」
  └────┘ └────┘ └────┘ └────┘
채점 뒤 해설: 「냉장고 안에 우유가 있어요. · 안 = 里面」 (빈칸에 실제 들어간 꼴을 보여 줌)
```

- 동사·형용사는 문장 속 꼴(주문했어요)을 빈칸으로 통째로 비우고, 카드는 사전형(주문하다)으로 낸다. 해설에서 실제 꼴을 보여 준다.
- 조사 뒤 붙는 부분(에, 를 …)은 빈칸 밖에 남는다(예문의 `[[ ]]` 범위 그대로).

## 3. 데이터

### 3.1 예문 표 `data/examples.csv`

| 칸 | 뜻 |
|---|---|
| `entry_id` | 단어 id(검토 표와 같음). 한 단어에 예문 하나 |
| `sentence_ko` | 한국어 예문, 대상 꼴을 `[[ ]]`로 정확히 한 번 감쌈 |
| `zh` | 간체 번역 |
| `status` | `cross`(일반·문학 교차 검토), `native`(원어민 확인), `hold`(앱에서 뺌) |
| `note` | 검토 메모(한국어) |

- 첫 내용: 재검수 109개(교차 검토 결과, 3장 「안」 포함)와 2장 「안」 예문. 모두 `status=cross`.
- 라이선스: 직접 쓴 예문이지만 같은 폴더 데이터와 맞춰 CC BY-SA 3.0(`data/LICENSE-data.md`에 한 줄).
- 검수표 페이지는 이 표에서 다시 만든다(원어민 의견은 이 표에 반영).

### 3.2 레슨 생성 (`tools/make_lessons.py`)

- `load_examples(path) -> {entry_id: {"pre", "form", "post", "zh"}}` — `hold` 제외. `[[ ]]`가 정확히 한 번이 아니면, 단어 id가 없으면, `zh`가 간체가 아니면 오류로 멈춘다.
- 문제 종류에 `fill`을 더한다. 예문이 있는 단어는 첫 바퀴에서 `fill`을 먼저 시도하고, 나머지 종류(韩→中, 中→韩, 음절)는 지금처럼 돌린다.
- `fill` 문제 모양(화면 코드가 이미 그리는 `choice`에 칸 하나 추가):
  `{"type": "choice", "concept": id, "q": "选出填入空白处的单词", "sentence": {"ko": "냉장고 ＿＿에 우유가 있어요.", "zh": "冰箱里有牛奶。"}, "options": [정답 ko, 오답 ko×3], "answer": 0, "explain": "냉장고 안에 우유가 있어요. · 안 = 里面"}`
- 오답: 中→韩와 같은 규칙(같은 장·같은 품사 우선, 정답과 뜻이나 한국어가 같은 단어 제외). 사전형이라 활용 생성은 없다.
- 레슨당 문제 수 규칙(max(6, 단어 수) + check 1)은 그대로. check 문제는 지금처럼 韩→中/中→韩만.

### 3.3 화면 (`src/ui/lesson.js`)

- `itemHead`가 `it.sentence`가 있으면 문제 머리 아래 예문 상자(한국어 큰 글자 + 중국어 작은 글자)를 그린다. 그 밖의 채점·흐름 코드는 그대로.
- 긴 예문은 줄바꿈(아이폰 SE 폭에서 넘침 없음), 한국어 단어 중간에서 끊지 않음(`word-break: keep-all`).

## 4. 시험

1. `tests/test_make_lessons.py`
   - 예문 있는 단어 → `sentence`가 있는 choice 문제가 생기고, `options[0]`이 단어의 사전형, 빈칸 `＿＿` 하나, `[[`가 남지 않음.
   - 예문 표에 `[[ ]]`가 0개·2개인 줄, 없는 단어 id, 번체 글자 → `load_examples` 오류.
   - `hold` 예문은 문제로 나오지 않음.
   - 예문 없는 단어만 있는 장은 생성 결과가 v0.3과 같음.
2. `tests/content.py`
   - `sentence`가 있는 문제: 빈칸 하나, 한글 문장, 중국어 간체, 보기 4개가 모두 한국어 사전형, 정답이 그 단어.
   - 성공 기준 1: 예문 있는(보류 아닌) 단어가 모두 빈칸 문제로 한 번 이상 나옴.
3. `tests/flow.py`
   - 예문 문제가 있는 레슨을 열면 예문 상자가 보이고, 카드를 골라 채점까지 됨. 아이폰 최소 폭·아이패드에서 넘침 없음.
   - 번체판에서도 예문 중국어가 번체로 보임(v0.3 변환).

## 5. 위험

- 예문은 원어민 검수 전이다(교차 검토만). `status`로 원어민 확인분을 구분해 두고, 문제가 보이면 `hold`로 바로 뺄 수 있다.
- 장 수준 문법은 어림이다. 앞 장 학습자에게 어려운 예문이 섞일 수 있다.
- 예문이 있는 단어는 문제 종류 배분이 바뀌어 일부 단어의 韩→中/中→韩 문제가 빈칸 문제로 대체된다(문제 수는 같음).
