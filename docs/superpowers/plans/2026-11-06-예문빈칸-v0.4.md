# 예문 빈칸 문제 v0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 예문이 있는 110개 단어를 「한국어 예문 빈칸 + 중국어 힌트 + 사전형 카드 4장」 문제로 한 번 이상 낸다.

**Architecture:** 예문은 `data/examples.csv` 한 곳에 둔다. 레슨 생성기가 예문 있는 단어의 첫 문제를 빈칸 문제로 만든다. 이 문제는 화면 코드가 이미 그리는 `choice` 문제에 `sentence` 칸 하나를 더한 모양이다. 화면은 문제 머리에 예문 상자만 더 그리고, 채점과 흐름은 그대로 둔다. 번체판은 v0.3 빌드 변환을 그대로 따라간다.

**Tech Stack:** v0.3과 같음.

**Spec:** `docs/superpowers/specs/2026-11-06-예문-빈칸-설계.md`

## Global Constraints

- 문제 머리 `q` = `选出填入空白处的单词`, 빈칸 글자 = `＿＿`(전각 밑줄 2개).
- 예문 표 칸: `entry_id,sentence_ko,zh,status,note`. `status` ∈ `cross`·`native`·`hold`. `hold`는 앱에 나오지 않는다.
- 카드는 사전형(단어 `ko`)만. 오답 규칙은 中→韩와 같다(같은 장·같은 품사 우선, 정답과 뜻이나 한국어가 같은 단어 제외).
- 레슨 수 254, 레슨 id, 레슨당 문제 수 규칙(max(6, 단어 수) + check 1)은 그대로. check 문제는 韩→中/中→韩만.
- 해설 = `<빈칸을 채운 예문> · <ko> = <zh>`.
- 커밋 메시지 끝: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` 와 `Claude-Session: https://claude.ai/code/session_01LbVuTL42jrrcUZwHJ2FNRK`.

## Review Focus

1. **빈칸이 둘로 보이거나 정답이 문장에 남음**(같은 단어가 예문에 두 번) → Task 2 `test_fill_item_shape`: 빈칸을 뺀 문장에 정답 ko가 다시 나오지 않음.
2. **보기에 정답이 둘로 보임**(오답 카드도 문맥에 맞는 동의어, 예: 비가 오다/비가 내리다) → Task 2 `content.py`의 같은 뜻 오답 검사가 빈칸 문제에도 적용됨.
3. **아이폰 좁은 화면에서 긴 예문이 넘침** → Task 3 `test_fill_sentence_fits`(iPhone 17e).
4. **예문 표 잘못된 줄**(괄호 0·2개, 없는 단어, 번체 글자, 모르는 status) → Task 1 `load_examples` 오류 시험.
5. **번체판에서 예문 중국어가 간체로 남음** → Task 3 `test_fill_in_hant`.

### Task 2: 빈칸 문제 만들기

**Files:**
- Modify: `tools/make_lessons.py`(`_item`, `_items`, `build_chapter`, `main`), `tests/test_make_lessons.py`, `tests/content.py`, `data/lessons/ch1–20.js`(생성물)

**Interfaces:**
- Consumes: Task 1 `load_examples`.
- Produces: `build_chapter(words, chapter, examples=None) -> dict`(기본 `None` = 예문 없음, v0.3과 같은 결과). `main(...)`은 `data/examples.csv`를 읽어 넘긴다.
  빈칸 문제 = `{"type": "choice", "concept": id, "q": "选出填入空白处的单词", "sentence": {"ko": pre + "＿＿" + post, "zh": zh}, "options": [ko, 오답 ko×3], "answer": 0, "explain": pre + form + post + " · " + ko + " = " + zh(뜻)}`.
  `_items`: 첫 바퀴(rnd 0)에서 예문 있는 단어는 `fill`을 먼저 시도하고, 안 되면(오답 부족) 지금 순서대로. 둘째 바퀴부터는 지금과 같다(`fill`은 다시 내지 않음). check 고르기는 그대로.

- [ ] **Step 1: 실패하는 시험** (`tests/test_make_lessons.py`, 픽스처 단어 + Task 1 방식의 예문 표):
  - `test_fill_item_shape` — 예문 있는 단어의 레슨에 `sentence`가 있는 choice가 하나 있고 `q`, `options[0] == 단어 ko`, 보기 4개 모두 같은 장 단어의 ko, `sentence["ko"].count("＿＿") == 1`, `"[[" not in sentence["ko"]`, 빈칸 뺀 문장에 정답 ko가 다시 나오지 않음, `explain`이 `저 사람은 학생이에요. · 사람 = `로 시작.
  - `test_fill_first_for_example_words` — 그 단어의 첫 문제가 빈칸 문제이고, 레슨 문제 수는 예문이 없을 때와 같음.
  - `test_no_examples_unchanged` — `build_chapter(words, 1)`과 `build_chapter(words, 1, {})`가 같은 JSON.
  - `test_hold_example_not_asked` — hold 줄만 있는 단어에는 `sentence` 문제가 없음.
